# Security Model

## Principles

1. Keep the service on `127.0.0.1` until authentication is implemented.
2. Use a dedicated, least-privilege Proxmox account.
3. Keep secrets only in `.env` or a secret-management system.
4. Treat Gemini responses as untrusted recommendations.
5. Test destructive actions only on non-critical resources.
6. Record who requested an operation and why.

## Credentials

Do not publish or log:

- `PROXMOX_TOKEN`.
- `GOOGLE_API_KEY`.
- `Authorization` headers.
- Passwords or `.env` files.

If a credential appears in a conversation, screenshot, log, or repository,
revoke it and generate a replacement. `.gitignore` excludes `.env`, but that
does not replace rotation of a credential that has already been exposed.

## Current attack surface

This branch does not implement API authentication. CORS also allows all
origins, and `/proxmox/power` accepts power actions without a resource
allowlist. Therefore:

- Do not publish port `8080` to the Internet.
- Do not expose it directly to an untrusted network.
- Do not use `--host 0.0.0.0` without authentication, TLS, and firewall rules.
- Restrict CORS to the dashboard's real origins.
- Add role-based authorization before enabling remote operations.

## Proxmox

The monitoring account should read only the required cluster scope. Power
permissions should be separated or limited by resource. Set
`PROXMOX_VERIFY_SSL=true` when the certificate is trusted; do not use disabled
certificate verification as a permanent fix for certificate configuration.

## AI

The AI receives telemetry, inventory, and the operator's question. Do not
include secrets, tokens, or unnecessary data in that context. Never execute
commands generated by Gemini. A recommendation must pass deterministic rules,
authorization, and human confirmation.

## Capabilities required before autonomy

`FinalBranch` does not yet implement:

- Configurable setpoints.
- Persistent rolling averages and historical storage.
- Resource allowlists.
- Protected-resource lists.
- Alert grace periods.
- Structured decision auditing.
- Human confirmation for power operations.
- Operator authentication.

These capabilities must be implemented before automatic shutdown is enabled.
